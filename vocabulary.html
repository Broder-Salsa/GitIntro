Git Terminology & Concept Cards

Master the language of version control, categorized by lifecycle stage and colored for quick reference.

Core Lifecycle

Repository (Repo)

A project folder being tracked by Git. It contains all files, folders, and the complete history of every change made over time.

Foundation
Core Lifecycle

Working Directory

The actual files you see and edit in your folder or code editor. These represent the current, uncommitted state of your work.

State
Core Lifecycle

Staging Area git add

A holding zone or "packing box" where you collect specific file changes before permanently saving them into history.

git add <file>
Core Lifecycle

Commit git commit

A permanent, timestamped snapshot (or checkpoint) of the files currently in the staging area, accompanied by a descriptive message.

git commit -m "msg"
Core Lifecycle

git init

The command that initializes a brand new, empty Git repository in an existing directory by creating a hidden .git folder.

git init
Core Lifecycle

git clone

The command used to download an existing remote repository from the cloud to your local machine, automatically setting up history and remote links.

git clone <url>
Core Lifecycle

git status

The sanity-check command that displays the state of your working directory and staging area (which files are modified, staged, or untracked).

git status
Core Lifecycle

git log

A command that displays the chronological history of past commits in the project.

git log --oneline
Remote Sync

Local vs. Remote

Local: The repository stored directly on your computer's drive.

Remote: The repository hosted in the cloud or on a server (such as GitHub).

Architecture
Remote Sync

Origin

The default nickname/alias Git gives to the remote repository URL that you cloned from.

origin
Remote Sync

Upstream

The target remote branch that a local branch is linked to for pushing and pulling.

-u / --set-upstream
Remote Sync

Push git push

Uploading your local commits up to the remote repository on GitHub.

git push -u origin <branch>
Remote Sync

Pull git pull

Downloading changes from the remote repository and immediately integrating them into your current local branch.

git pull origin master
Remote Sync

Fetch git fetch

Downloading changes and commits from the remote repository into your local system without automatically merging them into your working files.

git fetch origin
Branching & Collab

Branch

An independent, parallel workspace split off from the main project where you can build features or fix bugs without breaking the working code.

git switch -c <name>
Branching & Collab

Main / Master

The primary, official branch that contains the production-ready, working version of the application.

Primary Trunk
Branching & Collab

Fork

A personal copy of someone else’s GitHub repository created under your own GitHub account, often used for proposing changes in open-source projects.

GitHub Cloud Copy
Branching & Collab

Pull Request (PR)

A formal proposal created on GitHub asking the repository owner/team to review, test, and accept the code from your branch into main/master.

Review Proposal
Branching & Collab

Merge

The act of combining the commits and history from one branch into another.

git merge <branch>
Branching & Collab

Merge Conflict

A situation that occurs when two people modify the same lines of the same file in different ways, requiring a human to manually choose which code to keep.

Needs Human Touch
Branching & Collab

Stash git stash

A command that temporarily shelves (hides away) uncommitted changes so you can work on something else with a clean directory without committing unfinished work.

git stash / pop
Config & Safety

.gitignore

A text file placed in the root of the repository that explicitly tells Git which files, folders, or sensitive assets to completely ignore and never track.

.gitignore
Config & Safety

HEAD

A pointer or reference indicating which branch and commit your working directory is currently set to.

Current Pointer
